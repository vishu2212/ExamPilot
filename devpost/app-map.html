ExamPilot Architecture & App Map Production Verified

Interactive system architecture, deterministic kernel pipeline, and engineering practices implemented in ExamPilot.

Core Subsystems & Modules

1. Deterministic Scheduling src/lib/scheduler.js

Pure scheduling logic operating strictly on 30-minute integer units (1 unit = 0.5h).

  • Priority formula: importanceWeight × (6 − confidence) (range 1–15).
  • Starvation floor: Soft 1-hour minimum per topic, strictly subject to capacity precedence.
  • 2h Daily Cap: Diversifies daily study across maximum 2h per topic per day.
  • Review Buffer: Captures surplus capacity on final days before exam.

2. Schedule Diff Engine src/lib/diffEngine.js

Computes transparent, sentence-templated explanations from real before/after states.

  • Structured changes: Emits exact movement pairs, cuts, gains, and risk delta.
  • Earliest-day matching: Matches removals to additions earliest-day-first to discover moves.
  • No hardcoded scenarios: Sentences rendered dynamically from mathematical data.
  • Triage detection: Triggers when remaining effort exceeds available capacity.

3. State Machine & Reducer src/state/planReducer.js

Predictable state transitions ensuring invariant enforcement.

  • GENERATE: Initializes deterministic plan from form setup.
  • TOGGLE_BLOCK: Toggles completion state with daily capacity guard.
  • REPORT_MISSED: Deducts missed time from today; reschedules remaining work.
  • MARK_MASTERED / UNMASTER: Reallocates freed hours without moving completed blocks.
  • DAY_ADVANCED / RESET: Handles temporal shifts and clean state resets.

4. Defensive Storage src/lib/storage.js

Fault-tolerant persistence via localStorage key exampilot:v1.

  • Schema validation: isValidPlanState verifies types, dates, and invariants.
  • Safe quarantine: Malformed data copied to exampilot:v1:corrupt before reset.
  • User notice: Surfaced non-blocking banner if fresh state was initialized.
  • Atomic clear: Wipes all storage upon confirmed user reset.

The Golden Demo Lifecycle

1

Initial Feasible Plan (15h Needed / 16h Available)

CS 201: Data Structures loaded with 4 days @ 4h/day. Days 1–3 distribute Trees (5h), Graphs (5h), and Sorting (3h). Day 4 carries Sorting (1h), Arrays (2h), and a 1h review buffer.

2

Step A: Checking Off Day 1 Trees (2h)

Day 1 Trees block marked complete. Progress reaches 13%. Because Trees already consumed 2h on Day 1, remaining placements stay identical. No diff banner appears.

3

Step B: Reporting 2 Missed Hours on Day 1

Day 1 remaining free capacity drops to 0h. 13h of unfinished work must fit into 12h available across Days 2–4. Triage Mode triggers with a 1h deficit. Diff engine explains that Graphs moved to Days 3 & 4, while Sorting and Arrays were cut by 0.5h and flagged at risk.

4

Mastery Recovery: Marking Arrays Mastered

User marks Arrays as mastered in the sidebar. Its remaining 1.5h requirement is removed from future days. The freed time is reallocated to Sorting, clearing the 1h triage deficit and restoring the review buffer.
